## 2. Crumb Cafe OS — Cafe Operations & POS SaaS

<div align="center">

### Run the counter. Manage the menu. Track orders and expenses.

[![Live Application](https://img.shields.io/badge/Live%20Application-Visit%20Crumb-ef8b52?style=for-the-badge)](https://crumb.theabacuses.com)

[**☕ Explore Crumb Cafe OS →**](https://crumb.theabacuses.com)

</div>

**Crumb Cafe OS** is a cafe operations platform that brings together point-of-sale workflows, menu management, a cafe-specific storefront, order handling, customer records, expense tracking, and reporting.

### Product capabilities

- **Point of sale (POS)** — build a cart, calculate a sale, and record order details.
- **Menu and categories** — manage menu categories and items, prices, descriptions, and availability.
- **Cafe storefront** — provide a public cafe-specific menu and an order-request flow.
- **Order management** — review orders, inspect line items, and update order details and status.
- **Customer records** — associate customer contact details with orders.
- **Expense tracking** — record operating expenses with categories, amounts, dates, and notes.
- **Sales and expense reports** — review date-filtered summaries, item performance, and order/expense ledgers.
- **Cafe workspace and settings** — maintain cafe profile information and workspace-specific operational data.
- **Responsive, PWA-oriented interface** — support browser-based access across screen sizes.

### Engineering focus

Crumb Cafe OS demonstrates how software can support a real operational domain: menu and order data, POS transactions, customer information, expense tracking, and management reporting in a connected workflow.

### Technology

**Laravel 12 · PHP 8.2+ · MySQL/MariaDB · Blade · CSS · Vanilla JavaScript · Laravel Query Builder**

## 3. RelayOps — Incident & Team Management Platform

<div align="center">

### Track incidents. Coordinate teams. Preserve operational state.

[![Live Application](https://img.shields.io/badge/Live%20Application-Open%20RelayOps-2867C7?style=for-the-badge)](https://relayops.onrender.com)
[![GitHub Repository](https://img.shields.io/badge/GitHub-View%20Source-181717?style=for-the-badge&logo=github&logoColor=white)](https://github.com/mazhar1419/RelayOps)

[**⚙️ Explore RelayOps Live →**](https://relayops.onrender.com) · [**Review the source code →**](https://github.com/mazhar1419/RelayOps)

</div>

**RelayOps** is a full-stack incident and team management application built to demonstrate practical backend engineering, API integration, persistent state changes, and frontend-to-backend workflows.

### Implemented workflows

- **Incident creation** — create incidents and display them in the incident list.
- **Incident listing and status updates** — review incidents and change their status.
- **Persistent updates** — incident changes remain saved after refresh.
- **Team dashboard** — access team-related dashboard workflows.
- **Team management APIs** — create and list teams through backend routes.
- **REST API integration** — connect the React frontend with the Node.js/Express API.
- **Relational persistence** — store application records in PostgreSQL.
- **Version-aware incident updates** — support versioning in incident update operations and resolution tracking in the repository implementation.

### Technology

**Node.js · Express.js · React · PostgreSQL · REST APIs · Vitest**

### Engineering focus

RelayOps is the most direct public code sample for my Node.js work. It demonstrates API design, database-backed workflows, frontend integration, incident state management, and attention to persistence and update consistency.

## 🧠 How I Approach Software Development

- **Understand the problem first** — clarify business requirements, constraints, and user workflows.
- **Model the domain** — structure data around real entities, relationships, and ownership boundaries.
- **Build useful APIs** — validate inputs and keep responsibilities understandable.
- **Protect data integrity** — handle persistence, errors, and state transitions carefully.
- **Consider failure cases** — think about invalid input, edge cases, and unexpected states.
- **Deliver usable software** — consider the interface, deployment environment, and real-world operation.
- **Keep scope honest** — distinguish implemented functionality from future improvements and unverified assumptions.
